# Удалённый браузер через WireDesk

Браузер и авторизация остаются на Windows. На Mac доступны изображение
вкладки, мышь, ввод, прокрутка и стандартный CDP для автоматических проверок.
Используется отдельный канал, не занимающий exec-слот или PTY-слот. Оба вида
`wd` продолжают работать при открытом браузере.

## Подготовка

1. Обновить Mac GUI и CLI из одного workspace. Сначала Mac, затем Windows
   host. Старый host продолжит обслуживать терминал; браузерный сервис покажет
   ожидание protocol v4 и не отправит неизвестные опкоды старому хосту.
2. На Windows открыть Chrome под обычным пользователем с отдельным профилем
   и аргументами `--remote-debugging-address=127.0.0.1`,
   `--remote-debugging-port=19222`, `--user-data-dir=<отдельный каталог>`.
   Не использовать рабочий каталог профиля Chrome и не отключать sandbox.
   В отдельном профиле один раз войти в нужные рабочие приложения.
   Проверить, что порт слушает только loopback. Хост WireDesk обращается
   исключительно к `127.0.0.1:19222`; произвольные адреса не пробрасываются.
   Для автоматического запуска Chrome вместе с хостом включить в настройках
   Windows WireDesk **Start browser for remote access**, затем **Restart**.
   Либо задать `start_browser = true` в верхней части `config.toml`, до
   секций `[bluetooth]` и `[rfcomm]`, и перезапустить хост.
   По умолчанию опция выключена. Используется тот же профиль
   `%LOCALAPPDATA%\WireDeskBrowser`; открытый CDP-порт повторно не запускается.
   Chrome запускается через обычный Windows Explorer, без прав администратора;
   хост и рабочий стол должны работать под одной учётной записью Windows.
   При недоступном или повышенном Explorer запуск отменяется и записывается
   в лог. Закрытие хоста не закрывает Chrome. Если закрыть Chrome вручную,
   для повторного запуска нужно перезапустить хост или открыть Chrome вручную.
   Это запуск при старте, а не постоянное восстановление закрытого браузера.
3. На Mac собрать приложение и открыть его:

```sh
./scripts/build-mac-app.sh
open target/release/WireDesk.app
```

Браузерный доступ запускается внутри Mac GUI автоматически. Отдельный
`wd-browser` не нужен; если он был запущен вручную, закрыть его перед
обновлением GUI, чтобы освободить порты. После разрыва связи сервис сам
переподключается через GUI IPC, не открывая serial-порт самостоятельно.
Когда панель не открыта, сервис не запрашивает вкладки или кадры и не
передаёт браузерные данные по WireDesk. Оба терминальных слота свободны.

## Адрес без порта на Mac

Один раз собрать помощник и установить его:

```sh
cargo build --release --locked -p wiredesk-browser-cli --bin wd-web-forwarder
sudo /bin/bash scripts/install-browser-address.sh
```

Затем перезапустить обновлённое Mac-приложение. Порт `127.0.0.1:80`
открывает launchd; помощник работает от `nobody` и передаёт запросы только
на `127.0.0.1:19223`. Доступ из сети не открывается. Проверка ключа остаётся
в приложении. DNS, hosts и firewall не меняются. Установщик создаёт только
`/Library/PrivilegedHelperTools/dev.kar43lov.wiredesk-web-forwarder` и
`/Library/LaunchDaemons/dev.kar43lov.wiredesk-web-forwarder.plist`,
не перезаписывает существующие файлы и убирает свои файлы при сбое установки.
Без установленного помощника GUI использует прежний адрес с портом.

## Панель

### Весь экран Windows

Хост поколения 5 добавляет режим **Экран Windows** в селектор панели.
Он показывает основной монитор текущего рабочего стола, включая обычный
Chrome с его профилем, проводник и другие окна. Новый сеанс Windows не
создаётся. Кадры JPEG уменьшаются до 1280 пикселей по ширине, качество 75;
автообновление примерно раз в секунду, следующий кадр запрашивается только
после предыдущего. Когда режим выключен или панель скрыта, автоматические
запросы кадров не идут. Ключ доступа нужен для кадров и ввода.

В Mac-приложении нажать синюю кнопку **Экран Windows** рядом с **Capture Input**
или **Control+Command+Enter**: окно займёт выбранный дисплей, а после первого
кадра автоматически включится захват мыши и клавиш. Повторное
**Control+Command+Enter** закроет этот режим и освободит ввод.
**Cmd+Esc** освобождает ввод, **Cmd+Enter** переключает полный экран.
Картинка сохраняет пропорции; координаты мыши учитывают чёрные поля.
После ошибки кадра или разрыва связи захват освобождается; когда картинка
вернётся, **Cmd+Esc** снова включает ввод. **Control+Command+Enter** обрабатывается
на Mac и не передаётся в Windows.
Без захвата можно только наблюдать экран. Свёрнутое приложение не запрашивает
новые кадры. Режим по умолчанию выключен и не занимает терминальные слоты.

В браузерной панели доступны клик, правый клик, прокрутка, текст и сочетания
клавиш. Перетаскивание отправляется целиком при отпускании мыши; в Mac-окне
перетаскивание идёт через обычный поток ввода. Системные сочетания, которые
перехватывает сам браузер, удобнее выполнять в Mac-окне WireDesk.
Экран блокировки и защищённый рабочий стол UAC не поддерживаются.
Дополнительные мониторы и плавное видео в этом режиме пока не реализованы.

Передача использует ограниченный канал браузерных потоков и его подтверждения,
а не `wd --exec`: оба shell-слота остаются свободными. На Windows обработчик
кадров работает внутри хоста, без нового HTTP-порта или процесса. Старый хост
поколения 4 продолжает обслуживать браузер и терминалы, а при выборе экрана
панель предлагает обновить хост; новые пакеты старому хосту не отправляются.

В настройках Mac GUI, в блоке «Браузер через Windows», нажать
**Открыть браузер** или **Скопировать ссылку**. Постоянный адрес панели —
`http://wiredesk.localhost/` после одноразовой установки помощника выше.
До установки приложение показывает `http://wiredesk.localhost:19223/`.
Chrome разрешает имена внутри `.localhost`
в loopback без правки системного hosts. Прежние адреса `localhost:19223`
и `127.0.0.1:19223` также работают. Ссылка содержит ключ в URL-фрагменте и сразу
подключает панель; ключ не передаётся в HTTP-запросе адреса страницы.
При копировании ключ остаётся только в буфере Mac и не синхронизируется
на Windows. Не передавать ссылку другим людям.

Можно открыть адрес панели вручную, ввести токен из
`~/Library/Application Support/WireDesk/browser-token` и нажать «Подключиться».
Файл создаётся с правами `0600`, каталог — `0700`. Токен не попадает в исходники,
ответ discovery или Windows Chrome. Не передавать файл другим людям.

Выбрать вкладку. Доступны адрес страницы, клик по изображению, прокрутка,
клавиатура и отдельное поле для вставки текста. Автообновление выключено
по умолчанию; включение запрашивает новый PNG примерно раз в секунду,
не накапливая запросы кадров. Размер представления — 1280×800.

Панель показывает содержимое страницы; системные диалоги Windows и chrome
самого браузера в изображение не входят. Автоматические проверки и ручные
действия обращаются к одному браузеру: согласовывать, кто в данный момент
меняет вкладку. Для параллельных независимых проверок использовать разные
вкладки. Можно держать до восьми TCP-соединений.

## Автоматические проверки

Стандартный endpoint — `http://127.0.0.1:19222`. Во всех HTTP/WebSocket-запросах
нужен `Authorization: Bearer <токен>`. Например, в уже установленном Playwright:

```js
const fs = require('node:fs');
const os = require('node:os');
const path = require('node:path');
const { chromium } = require('playwright');
const token = fs.readFileSync(path.join(os.homedir(),
  'Library/Application Support/WireDesk/browser-token'), 'utf8').trim();
const browser = await chromium.connectOverCDP('http://127.0.0.1:19222', {
  headers: { Authorization: `Bearer ${token}` },
  noDefaults: true // Playwright 1.60+: preserve the existing context settings
});
const page = browser.contexts()[0].pages()[0];
console.log(await page.title());
await page.screenshot({ path: 'remote-page.png' });
// disconnect; do not close the user's remote browser
await browser.close();
```

`noDefaults` добавлен в Playwright 1.60 и сохраняет настройки существующего
контекста при подключении: https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp-option-no-defaults.

CDP-подключение поддерживается для Chromium; оно отличается от собственного
протокола Playwright и не даёт всех возможностей `browserType.connect`.
Документация: https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp.

## Передача и параллельность

- Опкод `Browser=0x50` добавлен отдельно; прежние payload и номера shell
  опкодов не менялись. В IPC вариант Browser добавлен в конец enum.
- По каждому TCP-потоку передаются смещение и подтверждение записанных байтов.
  Пропущенные блоки и подтверждения повторяются, дубликаты не записываются
  в TCP повторно. Существующий CRC пакета проверяется до доставки данных.
- Во всех браузерных потоках одного направления одновременно подтверждения
  ждут не более двух блоков, около 8 КБ. Остальные данные остаются в TCP,
  а не заполняют очередь WireDesk.
- Хост отправляет не более одного браузерного пакета за tick после обработки
  обоих shell-слотов. Подключение к Chrome и чтение/запись сокетов идут
  в отдельных потоках и не блокируют session tick.
- Разрыв GUI IPC, heartbeat timeout и новый handshake закрывают браузерные
  потоки; прежние exec/PTY ownership и маршрутизация сохранены.
- Удаление companion не закрывает сам Chrome. Когда доступ больше не нужен,
  закрыть отдельный браузер с отладочным портом. При выходе из Mac GUI
  встроенный сервис закрывает свои слушатели и IPC-соединение.

Отдельно проверен простой без открытых панелей и native-экрана: тест

остаются; без просмотра нет захвата, кодирования кадров и браузерной передачи.

После пользовательской сборки на Windows проверен запуск непосредственно
из `C:\Download\prjcts\wiredesk\target\release\wiredesk-host.exe`:
путь процесса и хэш совпали с собранным exe, репозиторий — `9839d5e`.

JPEG рабочего стола получен за 3,201 с (156719 байт).

`start_browser = false`, listener на `19222` отсутствовал. Это не мешало
desktop-режиму и терминалам; автозапуск Chrome включается отдельной настройкой.

Перед отправкой проверить физический хоткей: окно WireDesk в фокусе,
в Settings выбран дисплей; первый аккорд открывает экран и захватывает ввод,
второй возвращает геометрию окна и освобождает ввод. Затем повторить обычные
Cmd+Enter/Cmd+Esc и проверить, что Ctrl не остался нажатым на Windows.

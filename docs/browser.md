# Удалённый браузер через WireDesk

Браузер и авторизация остаются на Windows. На Mac доступны изображение
вкладки, мышь, ввод, прокрутка и стандартный CDP для автоматических проверок.
Используется отдельный канал, не занимающий exec-слот или PTY-слот. Оба вида
`wd` продолжают работать при открытом браузере.

## Подготовка

1. Обновить Mac GUI и CLI из одного workspace. Сначала Mac, затем Windows
   host. Старый host продолжит обслуживать терминал; браузерный CLI сообщит,
   что требуется protocol v4, и не отправит неизвестные опкоды старому хосту.
2. На Windows открыть Chrome под обычным пользователем с отдельным профилем
   и аргументами `--remote-debugging-address=127.0.0.1`,
   `--remote-debugging-port=19222`, `--user-data-dir=<отдельный каталог>`.
   Не использовать рабочий каталог профиля Chrome и не отключать sandbox.
   В отдельном профиле один раз войти в нужные рабочие приложения.
   Проверить, что порт слушает только loopback. Хост WireDesk обращается
   исключительно к `127.0.0.1:19222`; произвольные адреса не пробрасываются.
3. На Mac собрать и запустить:

```sh
cargo build --release --workspace
./target/release/wd-browser
```

GUI WireDesk должен быть запущен и подключён. CLI не открывает serial-порт
сам и не переключает транспорт. После разрыва связи перезапустить CLI;
GUI и оба терминальных канала переподключаются прежним способом.

## Панель

Открыть `http://127.0.0.1:19223/`. Ввести токен из
`~/Library/Application Support/WireDesk/browser-token` и нажать «Подключиться».
Файл создаётся с правами `0600`, каталог — `0700`. Токен не попадает в исходники,
ответ discovery или Windows Chrome. Не передавать файл другим людям.

Выбрать вкладку. Доступны адрес страницы, клик по изображению, прокрутка,
клавиатура и отдельное поле для вставки текста. Автообновление выключено
по умолчанию; включение запрашивает новый PNG примерно раз в секунду,
не накапливая запросы кадров. Размер представления — 1280×800.

Панель показывает содержимое страницы; системные диалоги Windows и chrome
самого браузера в изображение не входят. Автоматические проверки и ручные
действия обращаются к одному браузеру: согласовывать, кто в данный момент
меняет вкладку. Для параллельных независимых проверок использовать разные
вкладки. Можно держать до восьми TCP-соединений.

## Автоматические проверки

Стандартный endpoint — `http://127.0.0.1:19222`. Во всех HTTP/WebSocket-запросах
нужен `Authorization: Bearer <токен>`. Например, в уже установленном Playwright:

```js
const fs = require('node:fs');
const os = require('node:os');
const path = require('node:path');
const { chromium } = require('playwright');
const token = fs.readFileSync(path.join(os.homedir(),
  'Library/Application Support/WireDesk/browser-token'), 'utf8').trim();
const browser = await chromium.connectOverCDP('http://127.0.0.1:19222', {
  headers: { Authorization: `Bearer ${token}` },
  noDefaults: true // Playwright 1.60+: preserve the existing context settings
});
const page = browser.contexts()[0].pages()[0];
console.log(await page.title());
await page.screenshot({ path: 'remote-page.png' });
// disconnect; do not close the user's remote browser
await browser.close();
```

`noDefaults` добавлен в Playwright 1.60 и сохраняет настройки существующего
контекста при подключении: https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp-option-no-defaults.

CDP-подключение поддерживается для Chromium; оно отличается от собственного
протокола Playwright и не даёт всех возможностей `browserType.connect`.
Документация: https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp.

## Передача и параллельность

- Опкод `Browser=0x50` добавлен отдельно; прежние payload и номера shell
  опкодов не менялись. В IPC вариант Browser добавлен в конец enum.
- По каждому TCP-потоку передаются смещение и подтверждение записанных байтов.
  Пропущенные блоки и подтверждения повторяются, дубликаты не записываются
  в TCP повторно. Существующий CRC пакета проверяется до доставки данных.
- Во всех браузерных потоках одного направления одновременно подтверждения
  ждут не более двух блоков, около 8 КБ. Остальные данные остаются в TCP,
  а не заполняют очередь WireDesk.
- Хост отправляет не более одного браузерного пакета за tick после обработки
  обоих shell-слотов. Подключение к Chrome и чтение/запись сокетов идут
  в отдельных потоках и не блокируют session tick.
- Разрыв GUI IPC, heartbeat timeout и новый handshake закрывают браузерные
  потоки; прежние exec/PTY ownership и маршрутизация сохранены.
- Удаление companion не закрывает сам Chrome. Когда доступ больше не нужен,
  закрыть отдельный браузер с отладочным портом и остановить `wd-browser`.

## Проверка перед отправкой

Проверить сборку и тесты workspace на Mac и Windows. На живом канале проверить:
discovery, подключение инструмента по WebSocket, ручной ввод и прокрутку,
целостность нескольких кадров, `wd --exec` и интерактивный `wd` при загрузке
кадров, закрытие companion, переподключение и отказ браузера против v3 host.
Тест потери блока и ACK в `wiredesk-browser` использует реальные TCP-сокеты
и сравнивает весь двусторонний поток байт, включая повторную доставку.

### Живая проверка 12 октября 2026

На действующем канале одновременно работали интерактивный `wd`, `wd --exec`
и CDP с десятью PNG-кадрами. Вывод exec размером 256 КБ доставлен без потерь
за 1,27 с; отклик PTY — 0,055–0,194 с. Кадры размером около 56 КБ приходили
за 1,1–1,2 с, первый кадр под нагрузкой — за 1,82 с. Проверены CRC всех PNG.
Это замер конкретного канала и страницы, а не гарантия частоты кадров.

Проверены discovery, Playwright, клик в панели, русский ввод, Enter в
многострочном поле, перетаскивание и автообновление. Использовалась тестовая
страница с таблицей и формой; рабочие приложения Дознания, МУП и Справочников
в этой проверке не открывались. Пользовательский Chrome блокировал localhost
через расширение; UI прошёл проверку в отдельном профиле установленного
Chrome с включённым sandbox. Если localhost блокируется в рабочем профиле
Mac, панель нужно открывать в отдельном разрешённом профиле браузера.

Проверены отказ браузерного CLI против v3 host и сохранение терминальных
каналов. После теста исходные процессы и приложение WireDesk восстановлены;
временный Chrome и созданный тестом токен удалены.
